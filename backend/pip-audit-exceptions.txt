# pip-audit exceptions for the BLOCKING production dependency audit
#
#   python scripts/audit_dependencies.py        (run from backend/; CI runs the same)
#
# The audit covers requirements.txt (runtime only) INCLUDING transitive
# dependencies, and fails on any advisory that is not listed here. A new
# advisory therefore breaks CI until it is either fixed (bump the pin) or
# triaged into this file with a reason.
#
# RULES
#   * One advisory ID per line (PYSEC-/GHSA-/CVE-). '#' starts a comment.
#   * Every block MUST say what it is, why it is not blocking, and
#     "Remove when:" — tests/test_ci_config.py enforces the shape.
#   * Never add an ID just to get CI green: verify the affected API/feature is
#     really unused (or that no compatible fix exists) and write that down.
#   * Delete entries as the upgrades land. Baseline triaged 2026-09-21 against
#     the versions pinned in requirements.txt; see SECURITY.md "Dependency
#     Security" for the summary.
#
# HISTORY
#   * 2026-09-21: PYSEC-2026-1941 (starlette multipart upload parsing) REMOVED —
#     resolved by fastapi 0.115.5 -> 0.116.1 with starlette 0.41.3 -> 0.47.3

#     reports it, and reports nothing that is not listed below.

# --- starlette 0.47.3 (3/3): urlencoded form limits ignored --------------------
# Category: APPLICABLE, MITIGATED by a compensating control — NOT fixed. The fix
# needs a MAJOR upgrade (1.3.1); the fastapi 0.116.1 / starlette 0.47.3 upgrade
# does not resolve it (0.x has no fix).
# The flaw: Starlette ignores max_fields / max_part_size for
# application/x-www-form-urlencoded bodies, so an unauthenticated client could
# send an arbitrarily large urlencoded body to POST /api/v1/auth/login (parsed
# before authentication and rate limiting run; ~17 s of event-loop time at 1 MiB).
# Why not blocking: the flaw is compensated by the control below. Why it is still
# listed anyway: the vulnerable Starlette code is still present and reachable in
# principle — pip-audit keys on the package version, and adding a middleware does
# not change that. It is listed because it is compensated, not because it is gone.
# Compensating control: app/core/body_limit.py rejects urlencoded bodies over
# MAX_FORM_BODY_KB (default 16 KiB; login sends ~170 bytes) with 413 BEFORE
# Starlette parses them, with or without Content-Length (chunked bodies are
# counted as they stream). Worst-case parse is ~0.1 s at the cap. Covered by
# tests/test_request_body_limit.py; the platform/edge limit and the per-IP login
# rate limit remain as further layers.
# Remove when: starlette >= 1.3.1 via a compatible FastAPI upgrade. Do NOT remove
# it because the middleware exists — remove it only when pip-audit stops reporting it.
PYSEC-2026-249
