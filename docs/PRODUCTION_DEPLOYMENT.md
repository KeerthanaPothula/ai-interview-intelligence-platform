# Production Deployment Guide

Architecture: **Neon PostgreSQL** (database) → **Render** (backend) → **Vercel** (frontend)

```
Browser
  │
  ▼
┌─────────────────────────────────┐
│ Vercel — Static Site             │  https://<your-app>.vercel.app
│ React + Vite build               │
│ vercel.json: SPA rewrites        │
└──────────────┬──────────────────┘
               │ HTTPS + JWT (Authorization header)
               ▼
┌─────────────────────────────────┐
│ Render — Web Service             │  https://<your-app>.onrender.com
│ Docker: FastAPI + Uvicorn        │
│ Pre-deploy: alembic upgrade head │
└──────────────┬──────────────────┘
               │ postgresql+psycopg2 + SSL
               ▼
┌─────────────────────────────────┐
│ Neon — PostgreSQL                │  ep-<id>.<region>.aws.neon.tech
│ aiip_db                          │
│ SSL: sslmode=require             │
└─────────────────────────────────┘
```

Estimated monthly cost (all free tiers):
- Neon Free tier: $0 (5 GB storage, auto-suspend after 5 min idle)
- Render Free plan: $0 (512 MB RAM, spins down after 15 min idle)
- Vercel Hobby: $0
- **Total: $0/month**

> **Audio processing note**: Whisper and PyTorch require ~300–400 MB RAM at
> startup. On Render Free (512 MB) that leaves no headroom. `render.yaml`
> therefore sets `ENABLE_AUDIO_PROCESSING=false`. The frontend automatically
> hides the audio upload controls when this flag is off. All other features —
> resume upload, AI question generation, live interview, readiness score,
> reports, dashboard — remain fully functional. To enable audio later, upgrade
> to Render Starter ($7/mo) or Standard ($25/mo) and set
> `ENABLE_AUDIO_PROCESSING=true`.

## Step 1 — Neon PostgreSQL

### 1.1 Create the database

1. Go to [neon.tech](https://neon.tech) → Sign up / Log in.
2. **New Project** → Name: `aiip-production`.
3. **Database name**: `aiip_db` (or any name you prefer).
4. **Region**: choose `AWS us-east-2 (Ohio)` — matches the Render `ohio` region in `render.yaml` for lowest latency.
5. Click **Create Project**.

### 1.2 Get the connection string

1. On your project dashboard, click **Connection Details**.
2. Select **Connection string** → choose **psycopg2** from the dropdown.
3. Copy the string. It looks like:

   ```
   postgresql://aiip_db_owner:XXXXXXXX@ep-cool-name-123456.us-east-2.aws.neon.tech/aiip_db?sslmode=require
   ```

4. Prepend `+psycopg2` to make it SQLAlchemy-compatible:

   ```
   postgresql+psycopg2://aiip_db_owner:XXXXXXXX@ep-cool-name-123456.us-east-2.aws.neon.tech/aiip_db?sslmode=require
   ```

   This value is your `DATABASE_URL`. Store it securely — you will paste it into Render's environment variables in Step 2.

### 1.3 SSL

Neon enforces SSL on all connections. `sslmode=require` in the connection string is sufficient — psycopg2-binary on Linux (the Render container) supports SSL without extra configuration.

### 1.4 Migrations

Migrations run automatically before every Render deploy via `preDeployCommand: alembic upgrade head` in `render.yaml`. For the very first deploy:

1. The pre-deploy command runs, finds an empty database, and applies all migrations from scratch.
2. Subsequent deploys apply only new migrations — the command is idempotent.

To run migrations manually (e.g. to verify before deploy):
```bash
DATABASE_URL="postgresql+psycopg2://..." alembic upgrade head
```

### 1.5 Backups

Neon Free tier retains 7 days of point-in-time restore history. For the paid tier, configure **Logical Replication** or use Neon's built-in **Branching** for pre-migration snapshots.

## Step 2 — Render Backend

### 2.1 Connect the repository

1. [render.com](https://render.com) → New → **Blueprint** (uses `render.yaml`).
2. Connect your GitHub repository (`KeerthanaPothula/ai-interview-intelligence-platform`).
3. Render reads `render.yaml` at the repo root and shows you the `aiip-backend` service to create. Click **Apply**.

   > **Alternative**: New → **Web Service** → configure manually using the values in `render.yaml`.

### 2.2 Set the secret environment variables

In the Render dashboard → `aiip-backend` → **Environment**, add the following variables that are marked `sync: false` in `render.yaml`:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Your Neon connection string from Step 1.2 |
| `GEMINI_API_KEY` | Your Google AI Studio key |
| `CORS_ORIGINS` | Your Vercel frontend URL (set after Step 3, e.g. `https://aiip.vercel.app`) |

`JWT_SECRET_KEY` is auto-generated by Render (`generateValue: true`) — no action needed.

### 2.3 Plan selection

`render.yaml` requests the **Free** plan (512 MB RAM, $0/month). Audio processing is disabled (`ENABLE_AUDIO_PROCESSING=false`) to stay within the memory limit.

To upgrade later:
- **Starter** ($7/mo, 512 MB, no spin-down): set `plan: starter` in `render.yaml` — suitable for demo use without cold starts, but still no audio processing.
- **Standard** ($25/mo, 2 GB RAM): set `plan: standard` and `ENABLE_AUDIO_PROCESSING=true` — enables full Whisper transcription.

### 2.4 Cold starts

On the Free plan, the service spins down after 15 minutes of inactivity. The first request after spin-down takes **30–40 seconds** to respond while the container restarts. Subsequent requests are fast. This is expected behavior for the free tier.

### 2.5 First deploy

1. Click **Deploy** (or it starts automatically after the Blueprint is applied).
2. Watch the build logs — `pip install -r requirements.txt` fetches dependencies and takes 3–5 minutes on first build (no PyTorch on free tier, so it's faster than a full build).
3. After the image builds, the pre-deploy command runs: `alembic upgrade head`.
4. The web service starts. Check `/health` returns `{"status":"healthy","audio_processing_enabled":false,...}`.

### 2.6 Production URLs

After deploy, Render assigns a URL:
```
https://aiip-backend.onrender.com     ← example; actual subdomain may differ
```

Endpoints:
- Health: `https://aiip-backend.onrender.com/health`
- Readiness: `https://aiip-backend.onrender.com/ready`
- API docs: disabled in production (`DEBUG=false`) — use `/docs` locally only

## Step 3 — Vercel Frontend

### 3.1 Import the repository

1. [vercel.com](https://vercel.com) → New Project → Import from GitHub.
2. Select the repository `KeerthanaPothula/ai-interview-intelligence-platform`.
3. **Root Directory** → set to `frontend`. This tells Vercel the build lives in the `frontend/` subdirectory.
4. Vercel auto-detects Vite. Framework Preset: **Vite**. Build Command: `npm run build`. Output Directory: `dist`.

### 3.2 Set the environment variable

In the Vercel project → Settings → **Environment Variables**, add:

| Variable | Value |
|---|---|
| `VITE_API_BASE_URL` | `https://aiip-backend.onrender.com` (your Render URL, no trailing slash) |

> **Important**: `VITE_API_BASE_URL` is baked into the static bundle at build time by Vite. Changing it requires a redeploy. Set it *before* clicking Deploy.

### 3.3 SPA routing

`frontend/vercel.json` configures a catch-all rewrite so React Router handles all paths client-side:

```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

Without this, a hard refresh on `/sessions` or `/dashboard` would return a 404 from Vercel's CDN.

### 3.4 Deploy

Click **Deploy**. Vercel runs `npm run build` (TypeScript compile + Vite bundle) and serves the output from its global CDN.

Production URL:
```
https://aiip.vercel.app     ← example; your subdomain may differ
```

### 3.5 Update CORS on Render

After getting the Vercel URL, go back to the Render dashboard → `aiip-backend` → **Environment** and update:

```
CORS_ORIGINS = https://aiip.vercel.app
```

Trigger a manual redeploy of the backend for the change to take effect.

## Automatic deployments

Both platforms auto-deploy on push to `main`:

| Event | Action |
|---|---|
| `git push origin main` | Render rebuilds backend image + runs pre-deploy migration + hot-swaps the service |
| `git push origin main` | Vercel rebuilds frontend bundle + deploys to CDN in ~30s |

No manual steps required after the initial setup.

---

## Enabling audio processing (upgrading from free tier)

1. In the Render dashboard, change the service plan to **Standard** ($25/mo, 2 GB RAM).
2. Update `render.yaml`: set `plan: standard` and `ENABLE_AUDIO_PROCESSING: true`.
3. Add a disk block for uploaded audio files:
   ```yaml
   disk:
     name: uploads-disk
     mountPath: /app/uploads
     sizeGB: 10
   ```
4. Push to `main` — Render redeploys with the new plan and settings.
5. The frontend will detect `audio_processing_enabled: true` from `/health` and automatically show the audio upload controls.

## Known limitations

| Limitation | Impact |
|---|---|
| Audio upload disabled on free tier | Users cannot upload audio responses; live interview and text mode are unaffected |
| Render Free cold start | First request after 15 min idle takes ~30–40 s |
| Neon autosuspend (free tier) | First DB query after 5 min idle adds ~1–3 s |
| Single Uvicorn worker | Gemini calls queue under concurrent load |
| No persistent disk (free tier) | Ephemeral uploads lost on redeploy (moot when audio is disabled) |
| No password reset | Users who forget passwords cannot recover their account |

## Estimated idle memory (Render Free)

With `ENABLE_AUDIO_PROCESSING=false`:

| Component | RAM |
|---|---|
| Python runtime + OS | ~50 MB |
| FastAPI + SQLAlchemy + pydantic + httpx | ~80 MB |
| google-genai + other deps | ~30 MB |
| PyTorch / Whisper | 0 MB (never imported) |
| sentence-transformers model | 0 MB at idle (lazy, loads on first resume upload) |
| **Total idle** | **~160 MB** |

After the first resume is uploaded (sentence-transformers loads PyTorch):

| Component | RAM |
|---|---|
| Previous idle | ~160 MB |
| PyTorch + sentence-transformers model | ~240 MB |
| **Total after first embed** | **~400 MB** |

400 MB is comfortably within Render Free's 512 MB limit with ~110 MB headroom.
